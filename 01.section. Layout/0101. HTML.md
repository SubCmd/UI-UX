# Phase 1 — HTML 구조 (페이지의 뼈대)

> HTML은 '꾸미기'가 아니라 **'내용에 뜻을 붙이는 일'**임.
> 이 글이 제목인지, 메뉴인지, 본문인지를 기계(검색엔진·화면 읽어주는 보조기기)가 알아듣게 만드는 것

---

## 1-1. 태그란 무엇인가?

HTML은 **태그(tag)**라는 꺾쇠 표시로 내용을 감싸서 "이건 이런 거야"라고 알려줌.

```html
<p>안녕하세요</p>
```
- `<p>` = **여는 태그** (여기서 시작)
- `</p>` = **닫는 태그** (여기서 끝, 슬래스 `/`가 붙음)
- `p` = paragraph(문단)의 약자

> **용어 풀이 - 태그(tag)**
> 내용에 붙이는 '이름표', 내용을 여는 태그와 닫는 태그로 감싸면 "이 부분은 OO이다"라는 뜻이 됨.


### ❌ 나쁜 예 — 닫기 빼먹기 / 중첩 순서 꼬임

```html
<p>첫 문단
<p>둘째 문단        <!-- 앞 문단을 안 닫음 -->
 
<b><i>굵고 기울임</b></i>   <!-- 여는 순서와 닫는 순서가 어긋남 -->
```
> 닫기를 빼먹거나 순서가 꼬이면 브라우저가 제멋대로 해석해 화면이 깨짐
> 초보 오류의 절반이 여기서 나옴

### ✅ 좋은 예 — 꼭 닫고, 연 순서의 역순으로 닫기
```html
<p>첫 문단</p>
<p>둘째 문단</p>
 
<b><i>굵고 기울임</i></b>   <!-- 나중에 연 것을 먼저 닫음 -->
```
> **규칙:**
> 상자 안에 상자를 넣듯, **마지막에 연 것을 먼저 닫는다.**
> (양말 신고 신발 신었으면, 신발부터 벗는 것과 같음)

## 1-2. HTML 문서의 기본 뼈대

모든 HTML 파일은 이 틀에서 시작합니다.
 
```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>페이지 제목 (브라우저 탭에 뜸)</title>
</head>
<body>
  <!-- 화면에 보이는 내용은 전부 여기 -->
</body>
</html>
```

- `<head>` = 화면엔 안 보이지만 **페이지 정보**가 담기는 곳 (제목, 언어, 글자 인코딩)
- `<body>` = **실제로 화면에 보이는** 모든 내용
- `<meta charset="UTF-8">` = 한글이 깨지지 않게 하는 주문 (빼면 글자가 `ï¿½`처럼 깨짐)

> **비유:** `<head>`는 책의 '판권 정보·제목 페이지', `<body>`는 '실제 본문'이라고 생각하세요.

## 1-3. 제목과 문단 (h1~h6, p)

제목 태그 `<h1>`~`<h6>`는 **중요도(위계)**를 나타냄.
글자 크기를 위한 게 아님.

### ❌ 나쁜 예 — 크기 맞추려고 제목 태그를 골라 씀
```html
<h1>큰 글씨 필요해서 h1</h1>
<h4>좀 작게 하려고 h4</h4>
<h1>이 페이지에 h1이 또 등장</h1>   <!-- h1 여러 개 -->
```
> 제목 태그를 '글자 크기 조절 버튼'으로 쓰면, 기계는 글의 구조를 오해함.
> (크기는 나중에 CSS로 조절함.)

### ✅ 좋은 예 — 문서의 목차처럼 위계대로
```html
<h1>나의 포트폴리오</h1>    <!-- 페이지 대표 제목, 보통 1개 -->
  <h2>소개</h2>             <!-- 큰 단원 -->
  <h2>프로젝트</h2>
    <h3>프로젝트 A</h3>      <!-- 그 안의 소단원 -->
    <h3>프로젝트 B</h4>
  <h2>연락처</h2>

<p>여기는 일반 본문 내용입니다.</p>
```
> **규칙:** h1은 페이지당 1개, 단계를 건너뛰지 않기(h1 다음 바로 h3 ❌)
> 책의 '대제목 → 중제목 → 소제목' 목차라고 생각하면 쉬움.

## 1-4. 목록 (ul, il, li)

- `<ul>` = 순서 없는 목록 (점 ● 표시)
- `<ol>` = 순서 있는 목록 (1, 2, 3)
- `<li>` = 목록의 각 항목 (list item)


### ❌ 나쁜 예 — 줄바꿈으로 흉내 낸 가짜 목록
```html
- 사과<br>
- 바나나<br>
- 오렌지<br>
```
> 보기엔 목록 같지만 기계 눈엔 그냥 '글자 덩어리'임.
> 항목이 몇 개인지, 목록인지조차 알 수 없음.


### ✅ 좋은 예 — 진짜 목록 태그
```html
<ul>  <!-- ●, ●, ● 순서 -->
  <li>사과</li>
  <li>바나나</li>
  <li>오렌지</li>
</ul>
<ol>  <!-- 1, 2, 3번 순서 -->
  <li>사과</li>
  <li>바나나</li>
  <li>오렌지</li>
</ol>
```
> 이렇게 하면 "이건 3개짜리 목록"이라는 뜻이 명확해지고, 나중에 CSS로 점 모양·간격도 자유롭게 바꿀 수 있음.

## 1-5. 링크와 이미지 (a, img)

### 링크 — `<a>`
```html
<a href="https://example.com">방문할 곳 설명</a>
```
- `href` = 어디로 갈지 주소

#### ❌ 나쁜 예 — "여기", "클릭"
```html
자세한 내용은 <a href="/guide">여기</a>를 클릭하세요.
```
> "여기"만 보면 어디로 가는지 알 수 없습니다. 화면을 못 보는 사용자가 링크만 모아 들으면 "여기, 여기, 여기"만 들립니다.
 
#### ✅ 좋은 예 — 어디로 가는지 글자에 담기
```html
<a href="/guide">제품 사용 설명서</a>를 확인하세요.
```
 
### 이미지 — `<img>`
```html
<img src="assets/images/dog.jpg" alt="공을 물고 뛰어오는 골든리트리버">
```
- `src` = 이미지 파일 경로
- `alt` = 이미지가 안 뜰 때 대신 보일 글 / 화면 읽어주는 기기가 읽어줄 설명


#### ❌ 나쁜 예
```html
<img src="dog.jpg">                <!-- alt 없음 -->
<img src="dog.jpg" alt="이미지">    <!-- 의미 없는 alt -->
```
> `alt`가 없거나 "이미지"라고만 쓰면, 사진을 못 보는 사용자에겐 아무 정보도 안 됩니다. 검색엔진도 이 그림이 뭔지 모릅니다.
 
#### ✅ 좋은 예
```html
<img src="assets/images/dog.jpg" alt="공을 물고 뛰어오는 골든리트리버">
```
> **규칙:**
> `alt`에는 "이 그림이 무엇을 보여주는지"를 한 문장으로.
> (단, 순수 장식용 이미지는 `alt=""`로 비워둠)

## 1-6. 시맨틱 태그 - 이번 Phase의 진짜 핵심

`<div>`는 '아무 뜻 없는 빈 상자'임.
반면 시맨틱 태그는 이름만 봐도 역할을 함.

> 용어 풀이
> **시맨틱(semantic)** : '의미가 담긴'
> `<div>`(빈 상자) 대신 `<nav>`(메뉴 영역), `<header>`(머리말)처럼 이름이 곧 역할인 태그.

### ❌ 나쁜 예 — "div 수프" (전부 div)
```html
<div class="header">
  <div class="logo">내 사이트</div>
  <div class="menu">
    <div>홈</div>
    <div>소개</div>
  </div>
</div>
<div class="content">
  <div class="title">환영합니다</div>
  <div class="text">반갑습니다.</div>
</div>
<div class="footer">© 2026</div>
```
> 사람 눈엔 멀쩡해 보여도, 기계 눈엔 **전부 똑같은 빈 상자**입니다. 어디가 메뉴고 어디가 본문인지 알 길이 없어 검색 노출·접근성에서 손해를 봅니다.


### ✅ 좋은 예 — 의미 있는 뼈대
```html
<header>
  <h1>내 사이트</h1>
  <nav>
    <a href="/">홈</a>
    <a href="/about">소개</a>
  </nav>
</header>
 
<main>
  <section>
    <h2>환영합니다</h2>
    <p>반갑습니다.</p>
  </section>
</main>
 
<footer>© 2026</footer>
```


### 자주 쓰는 시맨틱 태그 6개

| 태그 | 역할 | 비유 |
|------|------|------|
| `<header>` | 페이지/구역의 머리말 (로고·제목) | 편지의 윗부분 |
| `<nav>` | 메뉴(내비게이션) 모음 | 건물 안내판 |
| `<main>` | 그 페이지의 핵심 본문 (페이지당 1개) | 책의 본문 |
| `<section>` | 주제로 묶인 한 덩어리 | 책의 한 '장(章)' |
| `<article>` | 그 자체로 독립적인 글 (블로그 글, 뉴스 한 건) | 신문의 기사 1건 |
| `<footer>` | 페이지/구역의 꼬리말 (저작권·연락처) | 편지의 맺음말 |


### 페이지 해부도 (머릿속에 그려두기!)

```
┌──────────────────────────────────────┐
│ <header>   로고 · 사이트 제목         │
│   <nav>    홈   소개   연락처         │
├──────────────────────────────────────┤
│ <main>                               │
│   ┌────────────────────────────────┐ │
│   │ <section> 소개                 │ │
│   │   <article> 글 1               │ │
│   │   <article> 글 2               │ │
│   └──────────────────────────────┘   │
│   ┌──────────────────────────────┐   │
│   │ <section> 연락처             │    │
│   └──────────────────────────────┘   │
├──────────────────────────────────────┤
│ <footer>   © 2026 · 이메일 · 링크     │
└──────────────────────────────────────┘
```
> **핵심 사고:**
> "이 부분을 한국어로 뭐라고 부를까?"를 먼저 생각하기!
> '머리말'이면 `<header>`, '메뉴'면 `<nav>`, '본문'이면 `<main>`.
> 마땅한 이름이 없을 때만 `<div>`를 사용!

## 1-7. 폼 기초 (form, label, input, bottom)

사용자에게 입력을 받는 부분임. (로그인, 검색, 신청서 등)

### ❌ 나쁜 예 — 라벨 없이 placeholder로 때우기
```html
<input type="text" placeholder="이메일">
<input type="password" placeholder="비밀번호">
<div onclick="...">전송</div>   <!-- 버튼인데 div -->
```
**왜 나쁜가**
- `placeholder`(흐릿한 안내 글자)는 **입력 시작하면 사라짐** → 사용자가 "이 칸이 뭐였지?" 하게 됨
- 화면 읽어주는 기기가 어떤 칸인지 제대로 안내 못 함
- `<div>`로 만든 버튼은 키보드로 누를 수 없음(접근성 문제)

### ✅ 좋은 예 — label로 칸과 설명을 연결
```html
<form>
  <label for="email">이메일</label>
  <input type="email" id="email" name="email">
 
  <label for="pw">비밀번호</label>
  <input type="password" id="pw" name="pw">
 
  <button type="submit">전송</button>
</form>
```
- `<label for="email">`의 `for`와 `<input id="email">`의 `id`를 **같은 이름**으로 맞추면 둘이 연결됨 → 라벨을 눌러도 입력칸이 선택됨
- 버튼은 `<div>`가 아니라 진짜 `<button>` 사용
- `type`을 `email`로 두면 폰에서 키보드가 이메일용으로 바뀌는 등 똑똑하게 동작

## 오늘의 실습 과제

스타일(CSS)은 아직 넣지 않음. 구조만 만듦

자기소개 페이지를 시맨틱 태그로 짜보세요. 포함할 것:
1. `<header>` 안에 이름(`<h1>`)과 `<nav>` 메뉴(소개·프로젝트·연락처)
2. `<main>` 안에 `<section>` 3개:
   - 소개: `<h2>` + `<p>` 한두 문단
   - 프로젝트: `<h2>` + `<ul>` 목록 3개
   - 연락처: `<h2>` + 간단한 `<form>` (이름·이메일 입력 + 전송 버튼)
3. 본인 사진 한 장 `<img>` (의미 있는 `alt` 포함)
4. `<footer>`에 저작권 표시

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>자기소개 페이지</title>
</head>
<body>  <!-- 모든 콘텐츠는 body 안으로 -->

<header>
  <h1>윤섭의 자기소개 페이지</h1>
  <nav>
    <!-- 메뉴 이동을 위한 네비게이션 링크 -->
    <a href="#intro">소개 </a> |
    <a href="#projects">프로젝트 </a> |
    <a href="#contact">연락처 </a>
  </nav>
</header>

<main>
  <!-- 1. 소개 섹션 -->
  <section id="intro">
    <h2>소개</h2>
    <p>안녕하세요! 주 3회 헬스, 주 3회 복싱을 즐기는 운동 마니아 윤섭입니다.</p>
    <p>꾸준한 기록을 통해 성장하는 것을 좋아합니다</p>

    <!-- 본인 사진 (의미 있는 alt 포함) -->
    <img src="my-photo.jpg" alt="운동하고 있는 윤섭의 프로필 사진">
  </section>

  <!-- 2. 프로젝트 섹션 -->
  <section id="projects">
    <h2>프로젝트</h2>
    <ul>
      <li>헬스 삼분할 운동 가이드</li>
      <li>복싱 훈련 가이드</li>
      <li>주짓수 기술 아카이빙</li>
    </ul>
  </section>

  <!-- 3. 연락처 섹션 -->
   <h2>연락처</h2>
    <form>
      <label for="username">이름</label>
      <input type="text" id="username" name="username" required> <!-- required: 이 칸은 필수 항목 -->

      <label for="email">이메일</label>
      <input type="email" id="email" name="email" required>

      <button type="submit">전송</button>
    </form>
  </section>
</main>

<footer>
  <p>&copy; 2026 윤섭. All rights reserved.</p> <!-- &copy: 저작권 기호 -->
/footer>

</body>
</html>
```
