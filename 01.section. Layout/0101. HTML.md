# Phase 1 — HTML 구조 (페이지의 뼈대)

> HTML은 '꾸미기'가 아니라 **'내용에 뜻을 붙이는 일'**임.
> 이 글이 제목인지, 메뉴인지, 본문인지를 기계(검색엔진·화면 읽어주는 보조기기)가 알아듣게 만드는 것

---

## 1-1. 태그란 무엇인가?

HTML은 **태그(tag)**라는 꺾쇠 표시로 내용을 감싸서 "이건 이런 거야"라고 알려줌.

```html
<p>안녕하세요</p>
```
- `<p>` = **여는 태그** (여기서 시작)
- `</p>` = **닫는 태그** (여기서 끝, 슬래스 `/`가 붙음)
- `p` = paragraph(문단)의 약자

> **용어 풀이 - 태그(tag)**
> 내용에 붙이는 '이름표', 내용을 여는 태그와 닫는 태그로 감싸면 "이 부분은 OO이다"라는 뜻이 됨.


### ❌ 나쁜 예 — 닫기 빼먹기 / 중첩 순서 꼬임

```html
<p>첫 문단
<p>둘째 문단        <!-- 앞 문단을 안 닫음 -->
 
<b><i>굵고 기울임</b></i>   <!-- 여는 순서와 닫는 순서가 어긋남 -->
```
> 닫기를 빼먹거나 순서가 꼬이면 브라우저가 제멋대로 해석해 화면이 깨짐
> 초보 오류의 절반이 여기서 나옴

### ✅ 좋은 예 — 꼭 닫고, 연 순서의 역순으로 닫기
```html
<p>첫 문단</p>
<p>둘째 문단</p>
 
<b><i>굵고 기울임</i></b>   <!-- 나중에 연 것을 먼저 닫음 -->
```
> **규칙:**
> 상자 안에 상자를 넣듯, **마지막에 연 것을 먼저 닫는다.**
> (양말 신고 신발 신었으면, 신발부터 벗는 것과 같음)

## 1-2. HTML 문서의 기본 뼈대

모든 HTML 파일은 이 틀에서 시작합니다.
 
```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>페이지 제목 (브라우저 탭에 뜸)</title>
</head>
<body>
  <!-- 화면에 보이는 내용은 전부 여기 -->
</body>
</html>
```

- `<head>` = 화면엔 안 보이지만 **페이지 정보**가 담기는 곳 (제목, 언어, 글자 인코딩)
- `<body>` = **실제로 화면에 보이는** 모든 내용
- `<meta charset="UTF-8">` = 한글이 깨지지 않게 하는 주문 (빼면 글자가 `ï¿½`처럼 깨짐)

> **비유:** `<head>`는 책의 '판권 정보·제목 페이지', `<body>`는 '실제 본문'이라고 생각하세요.

## 1-3. 제목과 문단 (h1~h6, p)

제목 태그 `<h1>`~`<h6>`는 **중요도(위계)**를 나타냄.
글자 크기를 위한 게 아님.

### ❌ 나쁜 예 — 크기 맞추려고 제목 태그를 골라 씀
```html
<h1>큰 글씨 필요해서 h1</h1>
<h4>좀 작게 하려고 h4</h4>
<h1>이 페이지에 h1이 또 등장</h1>   <!-- h1 여러 개 -->
```
> 제목 태그를 '글자 크기 조절 버튼'으로 쓰면, 기계는 글의 구조를 오해함.
> (크기는 나중에 CSS로 조절함.)

### ✅ 좋은 예 — 문서의 목차처럼 위계대로
```html
<h1>나의 포트폴리오</h1>    <!-- 페이지 대표 제목, 보통 1개 -->
  <h2>소개</h2>             <!-- 큰 단원 -->
  <h2>프로젝트</h2>
    <h3>프로젝트 A</h3>      <!-- 그 안의 소단원 -->
    <h3>프로젝트 B</h4>
  <h2>연락처</h2>

<p>여기는 일반 본문 내용입니다.</p>
```
> **규칙:** h1은 페이지당 1개, 단계를 건너뛰지 않기(h1 다음 바로 h3 ❌)
> 책의 '대제목 → 중제목 → 소제목' 목차라고 생각하면 쉬움.

## 1-4. 목록 (ul, il, li)

- `<ul>` = 순서 없는 목록 (점 ● 표시)
- `<ol>` = 순서 있는 목록 (1, 2, 3)
- `<li>` = 목록의 각 항목 (list item)


### ❌ 나쁜 예 — 줄바꿈으로 흉내 낸 가짜 목록
```html
- 사과<br>
- 바나나<br>
- 오렌지<br>
```
> 보기엔 목록 같지만 기계 눈엔 그냥 '글자 덩어리'임.
> 항목이 몇 개인지, 목록인지조차 알 수 없음.


### ✅ 좋은 예 — 진짜 목록 태그
```html
<ul>
  <li>사과</li>
  <li>바나나</li>
  <li>오렌지</li>
</ul>
```
> 이렇게 하면 "이건 3개짜리 목록"이라는 뜻이 명확해지고, 나중에 CSS로 점 모양·간격도 자유롭게 바꿀 수 있음.

## 1-5. 링크와 이미지 (a, img)

### 링크 — `<a>`
```html
<a href="https://example.com">방문할 곳 설명</a>
```
- `href` = 어디로 갈지 주소

#### ❌ 나쁜 예 — "여기", "클릭"
```html
자세한 내용은 <a href="/guide">여기</a>를 클릭하세요.
```
> "여기"만 보면 어디로 가는지 알 수 없습니다. 화면을 못 보는 사용자가 링크만 모아 들으면 "여기, 여기, 여기"만 들립니다.
 
#### ✅ 좋은 예 — 어디로 가는지 글자에 담기
```html
<a href="/guide">제품 사용 설명서</a>를 확인하세요.
```
 
### 이미지 — `<img>`
```html
<img src="assets/images/dog.jpg" alt="공을 물고 뛰어오는 골든리트리버">
```
- `src` = 이미지 파일 경로
- `alt` = 이미지가 안 뜰 때 대신 보일 글 / 화면 읽어주는 기기가 읽어줄 설명


#### ❌ 나쁜 예
```html
<img src="dog.jpg">                <!-- alt 없음 -->
<img src="dog.jpg" alt="이미지">    <!-- 의미 없는 alt -->
```
> `alt`가 없거나 "이미지"라고만 쓰면, 사진을 못 보는 사용자에겐 아무 정보도 안 됩니다. 검색엔진도 이 그림이 뭔지 모릅니다.
 
#### ✅ 좋은 예
```html
<img src="assets/images/dog.jpg" alt="공을 물고 뛰어오는 골든리트리버">
```
> **규칙:**
> `alt`에는 "이 그림이 무엇을 보여주는지"를 한 문장으로.
> (단, 순수 장식용 이미지는 `alt=""`로 비워둠)
