# 2-1. CSS를 HTML에 연결하는 법

CSS를 붙이는 방법은 3가지지만, 결론부터: 별도 파일(외부 CSS) 하나만 쓰기!

### ❌ 나쁜 예 — 태그마다 직접(inline) 스타일
```html
<p style="color:#333; font-size:18px;">문단 1</p>
<p style="color:#333; font-size:18px;">문단 2</p>
<p style="color:#333; font-size:18px;">문단 3</p>
```
> 같은 스타일을 매번 복사·붙여넣기
> 색을 바꾸려면 모든 줄을 일일이 고쳐야 함..
> 구조(HTML)와 꾸밈(CSS)이 뒤엉켜 지저분해집니다.

### ✅ 좋은 예 — 외부 CSS 파일 하나로
```html
<!-- index.html의 <head> 안 -->
<link rel="stylesheet" href="css/style.css">
```

```css
/* css/style.css */
p {
    color: #333;
    font-size: 18px;
}
```
> 스타일을 한 곳에 모아두니, 여기 한 줄만 바꾸면 모든 문단이 동시에 바뀜.
> (파이썬에서 설정값을 판 파일에 모으는 것과 같은 원리)

## 2-2. 선택자(selector) - 누구를 꾸밀지 고르기

> **용어 풀이 - 선택자**
> "이 요소들을 꾸며줘"라고 가리키는 손가락. 크게 3종류

```css
p        { }   /* 태그 선택자: 모든 <p>를 가리킴 */
.intro   { }   /* 클래스 선택자: class="intro"인 것들 (재사용 O) */
#header  { }   /* id 선택자: id="header"인 단 하나 (재사용 X) */
```

### ❌ 나쁜 예 — 똑같은 스타일을 id로 반복
```css
#title-1 { font-size: 24px; font-weight: bold;}
#title-2 { font-size: 24px; font-weight: bold;}
#title-3 { font-size: 24px; font-weight: bold;}
```
> 내용이 똑같은데 id로 세 번 반복
> id는 페이지에 하나뿐이어야 하는 이름이라 재사용이 안 됨.

### ✅ 좋은 예 — 재사용은 클래스로
```css
.section-title { font-size: 24px; font-weight: bold;}
```

```html
<h2 class="section-title">소개</h2>
<h2 class="section-title">프로젝트</h2>
<h2 class="section-title">연락처</h2>
```
> 규칙
> 여러 곳에 쓸 스타일 = clss
> 정말 페이지에 딱 하나뿐인 요소 = id (드물게)
> 초보 단계에선 거의 class만 사용해도 충분

## 2-3. 색 (color, background-color)

```css
body {
    color: #1a1a1a              /* 글자색 */
    background-color: #ffffff;  /* 배경색 */
}
```

> 색 적는 법: 이름(`red`), 16진수(`#ff0000`), rgb(`rgb(255,0,0)`).
> 실무에선 **16진수**를 가장 많이 사용함

### ❌ 나쁜 예
```css
body { background-color: black; color: #111; }  /* 배경 검정 + 글자 거의 검정 = 안 보임 */
```
> 배경과 글자색의 **대비**가 약하면 안 보입니다. 가장 흔하고 치명적인 실수입니다.

### ✅ 좋은 예
```css
body {
  background-color: #ffffff;
  color: #1a1a1a;  /* 순수 검정(#000)보다 살짝 부드러운 검정 → 눈이 편함 */
}
```
> 💡 미리 알아둘 팁(Phase 6에서 자세히)
> 순수 검정·순수 흰색을 100%로 부딪치게 하기보다 살짝 톤을 낮추면 더 고급스럽고 눈이 편함!!!

## 2-4. 글꼴·글자 크기 (font-family, font-size, line-height)

### ❌ 나쁜 예
```css
h1 { font-family: "내가좋아하는폰트"; }  /* 사용자 PC에 그 폰트가 없으면 깨짐 */
/* + 페이지에 폰트를 4~5종씩 섞어 씀 */
```
> 그 폰트가 없는 사람에겐 엉뚱한 글꼴로 보입니다. 폰트를 여러 종 섞으면 화면이 산만하고 싸 보입니다.
 
### ✅ 좋은 예 — 백업 목록 + 폰트는 1~2종
```css
body {
  font-family: "Pretendard", "Apple SD Gothic Neo", sans-serif;
  /* 앞 폰트 없으면 다음 것 → 결국 기본 고딕(sans-serif)으로 안전 착지 */
  font-size: 16px;
  line-height: 1.6;   /* 줄 간격: 가독성의 숨은 핵심 */
}
```
> **용어 풀이**
> - **폰트 fallback(백업 목록):** 앞 폰트가 없을 때 차례로 시도할 대체 글꼴 목록.
> 맨 끝엔 항상 `sans-serif`(고딕) 또는 `serif`(명조) 같은 일반 분류를 둠
> - **line-height(줄 간격):** 글 줄 사이 간격. `1.5~1.7` 정도가 읽기 편함.
> 너무 좁으면 답답하고, 너무 넓으면 한 덩어리로 안 읽힘

## 2-5. 박스 모델 — 이번 Phase의 핵심 ①
 
CSS의 모든 요소는 **'택배 상자'**입니다. 상자는 4겹으로 이뤄집니다.
 
```
┌──────────────────── margin (바깥 여백, 투명) ─────────────────┐
│   ┌──────────────── border (테두리) ─────────────────┐        │
│   │   ┌──────────── padding (안쪽 여백) ──────────┐  │       │
│   │   │                                          │   │       │
│   │   │            content (실제 내용)            │   │       │
│   │   │                                          │   │       │
│   │   └──────────────────────────────────────────┘   │       │
│   └──────────────────────────────────────────────────┘       │
└──────────────────────────────────────────────────────────────┘
```
 
> **가장 헷갈리는 두 가지 — padding vs margin**
> - **padding(안쪽 여백):** 내용과 테두리 *사이*의 공간. 상자 안의 완충재. (배경색이 여기까지 칠해짐)
> - **margin(바깥 여백):** 이 상자와 *다른 상자 사이*의 거리. (투명, 배경색 없음)
>
> 비유: padding은 '액자 안 여백(매트지)', margin은 '액자와 액자 사이 벽 간격'


### ❌ 나쁜 예 — 너비가 의도와 다르게 커짐
```css
.card {
  width: 300px;
  padding: 20px;
  border: 5px solid #ccc;
}
/* 기본 설정에선 실제 차지 너비 = 300 + 20*2 + 5*2 = 350px !
   "300으로 했는데 왜 삐져나오지?"의 범인 */
```
 
### ✅ 좋은 예 — box-sizing으로 길들이기
```css
* {
  box-sizing: border-box;
}
/* 이제 width:300px이면 padding·border 포함해서 '진짜 300px'.
   거의 모든 실무 프로젝트가 맨 위에 이 한 줄을 깝니다. */
 
.card {
  width: 300px;
  padding: 20px;
  border: 5px solid #ccc;   /* 전체 너비는 정확히 300px 유지 */
}
```
> **외워두기:**
> CSS 파일 맨 위에 `* { box-sizing: border-box; }` 한 줄
> 초보가 겪는 "왜 너비가 안 맞지?" 고통의 90%가 사라짐

## 2-6. 단위 — 이번 Phase의 핵심 ②
 
| 단위 | 기준 | 언제 쓰나 |
|------|------|-----------|
| `px` | 고정된 점 크기 | 테두리 두께처럼 작고 안 변해도 되는 값 |
| `%` | **부모 요소** 기준 비율 | 너비(반응형 대비) |
| `rem` | **전체(root) 글자 크기** 기준 | 글자 크기·여백 (예측 쉬움) ✅ |
| `em` | **자기 부모 글자 크기** 기준 | 곱해져서 헷갈림, 초보 비추천 |
